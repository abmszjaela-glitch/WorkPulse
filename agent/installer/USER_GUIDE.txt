WorkPulse Agent 1.0.0
Publisher display name: WorkPulse (provisional; not a verified legal identity)

OPENING AND STOPPING
Open WorkPulse Agent from the Start Menu or the optional desktop shortcut.
The native desktop window starts PAUSED, without a terminal. It displays the
employee login status, input counts, application name, active/idle durations,
last sync time, and tracking status. Inspect the working-hours policy.
Do not start activity tracking without applicable employee/organization
authorization. Installation and Windows sign-in startup do not authorize or
activate tracking. Emergency Stop and Pause are always in the tray menu.
A manual stop requires an explicit restart. Closing the window shuts down the
listeners and exits. Normal minimize keeps a taskbar window; the application
does not hide itself in an overflow-only tray. The tray can reopen the window.

START AND RESUME VALIDATION
Sign in with a valid employee account before starting. Signed-out, expired and
temporary-password accounts cannot start tracking from the window or tray.
Tracking also checks authentication while collecting, so logout/expiry stops
further input counts. Privacy acceptance and working-hours checks still apply.
Pause/resume keeps this employee's mouse, click, anonymous key and application
duration totals, plus active/idle durations. Paused time is excluded. Emergency
Stop keeps totals but requires an explicit authorized restart. Sign-out clears
the in-memory totals; application exit starts a new session on the next launch.

PRIVACY
Read PRIVACY.txt before use. Counts are anonymous input-event totals, not key
contents or text. No screenshots, window titles, URLs or document names are
collected. Application usage tracks process names and durations only.

EMPLOYEE SIGN-IN
Start the configured WorkPulse backend, open Sign in and use the account your
administrator created. The default development API is http://localhost:5000/api/v1.
Set SERVER_URL to the actual HTTPS API base for another computer/deployment;
localhost refers to this computer, not your administrator's computer. HTTP is
allowed only on loopback for local development. Redirects are not followed.
The server verifies the JWT through /auth/me before the app reports Signed in.
The green account card shows "Signed in successfully" and your verified email.
The main summary shows account status, local activity totals and tracking controls.
Sync and last-upload diagnostics are available through Details. After device
activation, authorized aggregated intervals are encrypted locally and sent to
the backend. Only server-acknowledged record IDs are removed from the queue.
Access tokens are saved only in Windows Credential Manager. Passwords are not
saved or logged. Cached access tokens are reverified on launch. Expiry pauses
tracking and requires sign-in again. Sign out pauses listeners, removes the
local token and attempts server session revocation. If offline, remote logout
cannot be confirmed and the UI says so.

New accounts require a temporary-password change: enter the current temporary
password, choose/confirm a new password, update, then sign in again. Tracking
does not start on login or password change. Accept the notice and explicitly
authorize Start / resume under the applicable policy.

DEVICE ACTIVATION
An administrator opens Employees, selects Connect Agent for your account, and
generates an activation code. After employee sign-in, open Connect device and
paste the code once. Review and accept the organization privacy policy. Wait for
server confirmation, then explicitly Start / Resume during your working hours.
Device activation and consent do not start tracking. An employee JWT is never a
device upload credential. Failed/offline uploads stay queued with bounded
retention; sending resumes when connectivity and authorization permit. The
backend database migrations must be deployed before synchronization can work.
The About menu shows
the Agent version and provisional publisher display. No digital signing or
verified publisher identity is claimed.

WORKING HOURS AND SETTINGS
The organization must configure the actual working hours and IANA timezone in
the dashboard Settings page. Connected Agents reload policy every 60 seconds;
policy changes pause the current run and require an explicit restart. An
unconfigured schedule blocks collection. The displayed remote policy is
authoritative for an activated device. Local bootstrap configuration accepts:
WORKING_TIMEZONE (IANA name), WORKING_START / WORKING_END (24-hour HH:MM),
WORKING_DAYS (Monday=0 through Sunday=6), DASHBOARD_URL and SERVER_URL.
Use authorized settings and restart transparently after policy changes.
Do not put passwords or JWTs in environment settings or plaintext files.

SHORTCUTS AND STARTUP
Desktop shortcut creation is optional and unchecked. Windows startup is also
optional and unchecked. Startup opens the visible application PAUSED; it does
not start tracking. Leaving the startup task unchecked makes no new startup
change. Existing startup preferences can be disabled or removed from the tray.

LOCAL DATA AND UNINSTALL
Normal queue/log data is per-user AppData, not Program Files. Operational logs
use fixed event messages and rotate. Token support uses Windows Credential
Manager; the queue support component protects aggregate payloads with DPAPI.
Uninstall through Windows Installed Apps or the Start Menu uninstall shortcut.
Uninstall retains activity data, logs, credentials and custom configuration;
no data-deletion task is offered. Any data removal requires a separate informed
retention decision. Other Windows users must disable their own startup setting.

DIAGNOSTICS
Errors are captured as privacy-safe fixed events in per-user WorkPulse logs.
Early configuration failures use a bounded startup-error.log when necessary.
If logging cannot work, tracking is stopped/blocked and an error is shown.
No security warning or organization policy should be bypassed. Windows 10/11 x64 are installer targets; consult actual
test evidence before deploying to an untested Windows build or environment.
